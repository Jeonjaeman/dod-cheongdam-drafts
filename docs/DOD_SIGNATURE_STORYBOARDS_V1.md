# 디오디 대표 장면 제안 v1 — 공동 평가 기반, 고객 승인 전

# 디오디피부과 청담 — 새 초안 3개 첫 2스크린 스토리보드

기존 저품질 초안은 폐기합니다. 아래는 레퍼런스 공동 평가 후 선정 제안이며, 타이포 px와 색은 모두 제안값입니다. 원본 사이트 측정값이 아닙니다. 브랜드는 병원이므로 기술 과시가 아닌 진료 신뢰가 기준입니다.

## 공통 기준(3안 동일 적용)
- 자산: 의료진·시설·효능을 합성하거나 실제처럼 연출 금지. 승인 자산 없을 때 추상 영상은 브랜드 장면으로만 쓰고 실제 진료 설명은 승인 콘텐츠 영역으로 분리.
- 구현: 전체 화면 WebGL도 장면 목적에 맞으면 사용. DOM 설명·문의는 접근 가능하게 유지. 프레임 스크럽(seek·시퀀스)은 Apple 분석 대기 중이라 확정 금지. 자동재생 영상 / seek / 이미지 시퀀스를 설계서에 구분 표기.
- 검증: 이미지 선명도(2x, 압축 아티팩트 없음), 모바일에서 PC와 동일 서사 순서, 문의·예약 버튼 상시 노출, reduced motion 시 정지 이미지로 대체, 키보드 포커스 순서 정상, 영상 로딩 실패 시 포스터 이미지와 텍스트만으로 메시지 전달.

## 안 1. 「진료가 머무는 공간」
- 고객 메시지: 한 사람의 피부 상태를 살피는 상담과 프라이빗 진료 경험. (기획 검토용 메시지)
- 출처: Lanserhof(경험 영상+예약 버튼), Locomotive(강한 영상→읽는 편집면), 봄결(인물 프레임→전면 확장, 한국어 2행), 더가든(실제 공간·의료진 영상+로고 연결선).
- 주 인터랙션: 스크롤로 프레임이 전면 확장되는 영상 전환.

| 스크롤 | 장면 |
|---|---|
| 0% | 중앙 좁은 세로 프레임에 브랜드 영상(승인 공간 영상 또는 추상 광 영상). 좌상 로고, 우상 예약 버튼 고정. 제목 2행 "피부를 보는 시간 / 디오디피부과 청담" 제안 56px. |
| 25% | 프레임이 화면 전면으로 확장, 텍스트는 작아져 하단으로. |
| 50% | 전면 영상 위 로고에서 가는 선이 내려와 2스크린 편집면 연결. |
| 75% | 편집면: 좌 승인 공간 사진, 우 진료 철학 본문 3문장과 진료 과목 목록. |
| 100% | 의료진 소개 카드(승인 사진+이름+경력)와 상담 CTA. |

- PC/모바일: PC는 좌우 2단 편집면. 모바일은 프레임을 가로 전폭 영상으로 시작해 세로 1단으로 동일 순서 유지.
- 필요 자산: 승인 공간 영상 1(15초 내, 포스터 포함), 공간 사진 3, 의료진 승인 사진·경력, 진료 철학 문구.
- 검증 기준: 공통 기준 + 영상 자동재생은 음소거·루프, seek 사용 안 함. 확장 전환은 CSS 변환으로만 구현.
- 기획팀 확인: 공간·의료진 촬영 승인 여부, 예약 버튼 연결(네이버/전화/폼), 영상 없을 때 추상 영상 대체 동의.

## 안 2. 「근거로 말하는 피부과」
- 고객 메시지: 피부를 살피고 진료 방향을 상담하는 과정. 임의 수치·인증·효능 주장은 사용하지 않음.
- 출처: Lusion(넓은 반사 하이라이트의 매끈한 입체, 장면 확대), Igloo(환경·바닥·반사가 만드는 공간), 셀파크(근거·연혁 편집).
- 주 인터랙션: 스크롤에 따라 중앙 오브젝트가 확대되며 근거 텍스트가 순서대로 고정 표시(스티키 텍스트 전환).

| 스크롤 | 장면 |
|---|---|
| 0% | 짙은 틸 배경 위 반사 바닥과 매끈한 추상 오브젝트(브랜드 장면). 제목 "근거 있는 피부 진료" 제안 48px, 우측 문의 버튼. |
| 25% | 오브젝트 확대 시작, 좌측에 첫 근거 문장 고정 노출. |
| 50% | 오브젝트가 화면을 채우며 부드럽게 흐려짐, 2스크린 진입. |
| 75% | 승인 콘텐츠 영역: 진단 장비 안내·의료진 소개·상담 과정. 공적 검증 전 인증 배지·미확인 연혁은 삽입하지 않음. |
| 100% | 시술 전 상담 절차 3단계 + 상담 신청 CTA. |

- PC/모바일: PC는 좌 텍스트 고정·우 오브젝트. 모바일은 오브젝트 상단, 텍스트 하단 순서로 동일 서사.
- 필요 자산: 실시간 three.js 렌즈·환경광/반사 자산·불투명 굴절 배경, 승인 B01 포스터, 의료진·장비 승인 사진. 생성 영상은 표면 텍스처 또는 별도 장면으로 사용할지 프로토타입에서 비교.
- 검증 기준: 공통 기준 + 오브젝트는 브랜드 장면 표기, 효능 암시 문구 금지. 실시간 3D의 포인터·스크롤·모바일 터치 반응, 텍스트 가림, 프레임 속도·발열을 실제 검증. 실패 시 승인 포스터와 같은 구도·설명 유지. matcap과 굴절은 다른 재질 기법이므로 전자는 표면 반사 참고, 후자는 실제 투과 테스트로 구분.
- 기획팀 확인: 공개 가능한 의료진·진단 장비 근거 범위, 의료광고 심의 필요 문구, 추상 오브젝트가 피부·시술을 연상시키지 않는지 검토.

## 안 3. 「한 장의 얼굴, 여러 장의 이야기」
- 고객 메시지: 한 사람의 피부를 오래 보는 병원.
- 출처: A24(큰 키아트+초대형 제목+작은 CTA), 1912(전체 이미지→작은 중심 이미지→여러 이미지 콜라주).
- 주 인터랙션: 스크롤에 따라 이미지가 축소·분할되어 콜라주로 재배치되는 레이아웃 전환(영상 없음).

| 스크롤 | 장면 |
|---|---|
| 0% | 전체 화면 키아트 1장(승인 공간 또는 추상 질감 사진). 초대형 제목 "DOD" 제안 160px, 하단 작은 CTA "상담 문의". |
| 25% | 키아트가 중앙 작은 사각형으로 축소, 여백에 한국어 부제 등장. |
| 50% | 축소 이미지 주변에 4~6장 사진이 콜라주로 배치. |
| 75% | 콜라주 각 장에 짧은 캡션(공간·진료 과목·의료진), 승인 콘텐츠 영역. |
| 100% | 진료 안내·위치·시간과 문의 CTA. |

- PC/모바일: PC는 6장 자유 배치 콜라주. 모바일도 중심 이미지 축소→주변 장면 출현을 유지하되, 화면 폭에 맞춰 궤적·크기·겹침을 별도로 아트디렉션. 단순 정적 2열 대체는 하지 않음, 제목 제안 72px.
- 필요 자산: 고해상 키아트 1, 승인 사진 6, 캡션 문구, 진료 안내 데이터.
- 검증 기준: 공통 기준 + 주 장면은 고품질 사진·타이포의 연속 변환으로 구성. 영상·WebGL이 필요하면 목적을 명시해 추가하며 기술을 일괄 금지하지 않음. 저속망에서도 첫 화면 1장 우선 로딩.
- 기획팀 확인: 키아트용 공간 사진 확보 여부, 콜라주에 환자 사진 사용 금지 확인, 영문 제목 사용 허용 여부.

## 구도·인터랙션 차별성 요약
| 안 | 구도 | 주 인터랙션 | 모션 매체 |
|---|---|---|---|
| 1 | 중앙 프레임→전면 | 프레임 확장 전환 | 자동재생 영상 |
| 2 | 좌 텍스트·우 오브젝트 | 실시간 카메라·오브젝트·텍스트 동기화 | three.js + 필요 시 영상 텍스처 |
| 3 | 전면 키아트→콜라주 | 레이아웃 재배치 | 정지 이미지만 |

권장 우선순위는 안 1입니다. 병원 신뢰와 자산 현실성이 가장 균형 잡혀 있고, 승인 영상이 없으면 안 3이 즉시 실행 가능한 대안입니다. 다음 단계는 기획팀 확인사항 회신 후 각 안의 와이어프레임 제작입니다.
## 선정과 구현 상태
리사 독립 평가 + 나주 기획 평가 + 소연 공개 소스 분석 + 니키타 모바일 캡처 평가를 합친 제안이다. 어떤 조합도 고객 승인이나 새 프로토타입 검수 완료를 뜻하지 않는다. 스크롤 퍼센트는 제안한 첫 두 화면 진행률이며 외부 레퍼런스 실측값이 아니다. 실제 시간축 모션·터치·프레임 스크럽 근거는 추가 검증 대상이다.
